# Рабочее пространство, приложения и ввод

## Запуск

`make run` выбирает Standard VGA QEMU и образ KFS2. `make run_kfs3` запускает тот
же рабочий стол поверх отдельного образа `kintsugi_kfs3_hdd.img` с POSIX-слоем
KFS3 (`make kfs3` создаёт образ). Режим по умолчанию — **1280×800**.
Команды `kset`, `kpaint`, `kiwi`, `kinfo` доступны через `/BIN` и PATH shell.
В KTUI: `w` — KiWi, `p` — Paint, `Shift+D` — настройки, `i` — информация.

## Пользователи, вход и root

При загрузке init показывает полноэкранный TUI-экран входа: только список
учётных записей из `/ETC/PASSWD` и, если у выбранного пользователя есть пароль,
поле ввода со звёздочками. Ни журнала загрузки, ни меню, ни системной панели на
экране входа нет; после выхода из оболочки он показывается заново.

По умолчанию существуют только `root` (uid 0) и `user` (uid 1000); последний
выбранный вход хранится в `/ETC/LASTUSER`, поэтому Enter сразу входит как
`user`. У `user` пустой пароль, у `root` — `root`.
Пароли хранятся не открытым текстом: `/ETC/SHADOW` содержит соль и итеративный
хеш FNV-1a; файл доступен только root (режим 0600), пять неудачных попыток
блокируют вход на 500 тиков.

Повышение прав выполняет `sugo` («superadmin gozaimasu»):

```text
sugo                    # корневая оболочка (как sudo без аргументов)
sugo shell              # то же самое
sugo useradd alice      # одна команда от имени root
sugo shutdown           # встроенная команда ядра выполняется как root
```

`KOS_SYS_BUILTIN` умеет выполнять встроенную команду с одноразовыми root-правами:
`shutdown`, `reboot`, `sync`, `end` и другие системные операции доступны через
`sugo`, а при попытке выполнить их от обычного пользователя shell печатает
`permission denied (root only) - use 'sugo <command>'`.

Root не нуждается в `sugo`. Команды `shutdown`, `reboot`, `end` и `sync` также
доступны обычному пользователю без повышения: машина рассматривается как
однопользовательская рабочая станция. Учётные записи создаются и обслуживаются
только root:

- `useradd <name>` — новый uid начиная с 1001, домашний каталог `/home/<name>`,
  пароль задаётся дважды;
- `userpswd <name>` — смена пароля (root может менять любой);
- `rootpswd` — смена пароля root;
- `userchange <name>` — записать LASTUSER и перезагрузиться для входа.

Права на отдельные файлы задаются утилитами `chmod 600 <path>` и
`chown <user|uid> <path>`. Поскольку у KFS2-inode нет поля владельца, POSIX-метаданные
хранятся обычным файлом `/etc/fsmeta` (`uid mode path`), загружаются ядром при
загрузке и перезаписываются при каждом изменении. Владелец может менять режим
своего файла; `chown` доступен только root.

Обычный пользователь не может создавать учётные записи, читать `/ETC/SHADOW`,
писать в системные каталоги или запускать системные сервисы. Ядро проверяет
uid/euid в syscalls, VFS и встроенных командах, поэтому обход через прямой
вызов syscall не работает.

## Настройки экрана и раскладки

В `kset`: 1024×768, 1280×800, 1440×900, 1600×900. Enter тестирует выбранный
режим; Y подтверждает. Через 10 секунд без подтверждения восстанавливается
предыдущий режим. S сохраняет `/ETC/VIDEO.CFG`, init применяет его при загрузке.

**F12** переключает EN/RU без зависимости от Alt+Shift хоста. Поддержаны также
Ctrl+Shift и Alt+Shift, в любом порядке нажатия. В KSet клавиша L явно меняет
раскладку. Если хост перехватывает комбинацию, используйте F12 или L.

## Мышь

Драйвер PS/2 получает пакеты IRQ12, отбрасывает overflow и синхронизирует
начало пакета. При загрузке он опрашивает IMPS/2 (последовательность `F3` со скоростями 200/100/80
и `F2`): если мышь отвечает ID `0x03`, включается четвёртый байт пакета с
относительным ходом колеса. Курсор рисуется поверх framebuffer с сохранением
фона. Общие меню выбираются мышью. В KC левый клик выбирает файл и панель,
правый открывает выбранное. В KiWi можно перетаскивать заголовки окон.

Колесо работает в двух местах: в shell оно прокручивает журнал терминала на
три строки за щелчок, а в TUI-приложениях `tui_event_read()` превращает его в
`TUI_SCROLL_UP`/`TUI_SCROLL_DOWN`, поэтому списки, редакторы и KCSV прокручиваются
без изменений в самих приложениях. USB-мышь по-прежнему не поддерживается;
QEMU эмулирует PS/2.

## KPaint

Экспериментальный редактор цветного **cell-art 72×17**, не пиксельный BMP-редактор.
Левая кнопка рисует, правая стирает. Палитра выбирается кликом или +/-.
Стрелки перемещают перо, Space рисует, P включает непрерывное перо.
S сохраняет, O открывает, N очищает, U меняет текущее и предыдущее состояние.
Несохранённые изменения требуют подтверждения при выходе.

Формат `.KPT`: `KPT1`, байт ширины (72), байт высоты (17), два нулевых
резервных байта, затем 1224 индекса VGA-палитры 0–15. Файлы проходят валидацию.
KC открывает `.KPT` в KPaint; `.ELF` запускает как программу, остальные — в KUNED.

## KiWi

KiWi — экспериментальная **in-process** оконная TUI-оболочка. Четыре встроенных
окна: приветствие, процессы, файлы `/HOME`, UTF-8 заметки. Tab меняет фокус,
F4 показывает все окна, вкладки выбираются кликом, `[x]` скрывает окно и
передаёт фокус следующему видимому. Ctrl+S сохраняет заметки в `$HOME/kiwi.txt`
(по умолчанию `/home/user/kiwi.txt`) — каталог `/home` root-owned, поэтому запись
туда была бы нарушением прав. F2 открывает приложения (включая KListen, KCSV,
KServices и KSerSys), F3 — темы. Заметки загружаются при запуске.

Внешние ELF запускаются **на полный экран**, и после завершения управление
возвращается KiWi. Это не оконный сервер с независимыми поверхностями процессов.
Несохранённые заметки требуют подтверждения при выходе; Ctrl+S сохраняет их.

### Файлы KiWi

В окне Files: стрелки вверх/вниз выбирают запись, Enter открывает каталог или
документ в KUNED, стрелка влево переходит к родителю. Левый клик выбирает строку.
N создаёт файл (без перезаписи существующего), D — каталог, R переименовывает,
X/Delete удаляет после подтверждения. Список пока ограничен 64 записями.
F2 открывает меню Programs: Paint, Editor, Vik, Commander, Settings, темы,
монитор, игры, Services, CSV table, KMines, K2048, KLife и KTmux.

### KFS3 и «всё есть файл»

**Основная ФС KFS3 — ext2.** Ядро монтирует ext2 (superblock, group descriptors,
inode/bitmap, block bitmap, direct/single/double indirect block map) как `/`,
а при его отсутствии откатывается к KFS2 и FAT12. Поддерживаются чтение, запись,
создание/удаление файлов и каталогов, rename, truncate и readdir. Образ создаётся
утилитой `tools/mkfs_ext2.py` через `mke2fs -d`, проверяется `e2fsck` и подключается
целью `make kfs3`/`make ext2` (`diskimgs/kintsugi_ext2_hdd.img`); `make run_kfs3`
загружает именно его.

Миграция со старого KFS2-образа:

```text
python3 tools/migrate_kfs2.py diskimgs/kintsugi_kfs2_hdd.img /tmp/kfs2-export
python3 tools/mkfs_ext2.py diskimgs/kintsugi_ext2_hdd.img --from /tmp/kfs2-export
```

Физические имена каталогов и файлов в образе **строчные** (`/bin`, `/etc`,
`/home`, `/var`, `/proc`, `/dev`). Поиск имён в драйверах регистронезависимый,
поэтому старые ссылки вида `/BIN/INIT.ELF` тоже работают.

Псевдофайлы KFS3 доступны только на чтение:

- `/proc/uptime`, `/proc/meminfo`, `/proc/version`, `/proc/cpuinfo`,
  `/proc/filesystems`, `/proc/mounts`, `/proc/self`;
- `/proc/<pid>/status`, `/proc/<pid>/cmdline`, `/proc/<pid>/comm`;
- `/dev/null`, `/dev/zero`, `/dev/random`, `/dev/urandom`, `/dev/tty`,
  `/dev/console`.

Это обычные файлы в VFS: они перечисляются в `ls`, имеют owner/mode и читаются
стандартными `cat`/`read`; `/dev/null` и `/dev/tty` допускают запись, остальные
псевдофайлы доступны только на чтение.

Права задаются при создании образа: системные каталоги `/etc` (кроме
`/etc/shadow`), `/bin`, `/usr`, `/boot`, `/var`, `/root`, `/man` принадлежат
root; `/home/<user>` — владельцу с режимом 0700/0600; `/tmp` — 0777/0666;
`/proc` только для чтения; `/dev` доступен всем. Форматтер:
`tools/mkfs_kfs2.py`, установщик: `tools/install_kfs2.py`; `make kfs2` и
`make kfs3` пересобирают образы. `make run_fat12` запускает legacy-режим FAT12.
Миграция произвольных данных из FAT12 не автоматизирована, старые образы не
изменяются.

Framebuffer имеет отдельную палитру, независимую от VGA/TUI-тем. Профили:
`system/themes/OCEAN.FBT` и `system/themes/AMBER.FBT`; Ocean включён по умолчанию.

### KCSV

`kcsv [file.csv]` — редактор таблиц. Enter правит ячейку, стрелки двигают
курсор, `a`/`A` добавляют строку/столбец, `d`/`D` удаляют, `i` вставляет,
`s` сортирует тело таблицы, `w` сохраняет, `n` создаёт новый файл. CSV
разбирается и сохраняется по RFC 4180 с экранированием кавычек. Несохранённые
изменения требуют подтверждения; размер файла ограничен 64 KiB.

### K2048

`k2048` — исправленная версия 2048: за ход каждое движение и слияние
учитывается один раз, плитка не появляется без изменения поля, победа
фиксируется при достижении 2048. Проигрыш определяется всегда, в том числе когда
заполненное поле не двигается ни в одном направлении (раньше в этом случае
игра зависала). После проигрыша ввод блокируется. Стрелки и WASD двигают,
`n` начинает заново, `q` выходит.

### KServices

`kservices` показывает сервисы, учётные записи и планировщик во вкладках
System/User/Accounts/Scheduler. Системные сервисы запускает только root; в
пользовательской сессии вкладка служит для просмотра, а действия доступны через
`sugo kservices`. Вкладка Accounts читает `/etc/passwd` и отмечает текущего
пользователя, Scheduler показывает pid, uid и приоритеты round-robin.

### KSerSys (Kintsugi Service System)

`ksersys` — systemd-подобный менеджер сервисов. Определения хранятся в
`/etc/services` как обычный текст:

```text
# name path scope account autostart restart enabled [args...]
clockd /BIN/KSDAEMON.ELF system root 1 1 1
mixer  /BIN/SOUNDCTL.ELF user  user  0 0 1
```

Init (PID 1) запускает `ksersys --supervise` при загрузке и перезапускает его,
если он завершился. Супервайзор стартует включённые сервисы с `autostart=1`,
наблюдает за ними через snapshot процессов, убирает зомби `wait()` и
перезапускает те, у кого `restart=1`. Каждому сервису можно задать учётную
запись: root использует одноразовое понижение прав через `KOS_SYS_ELEVATE`,
поэтому демон не унаследует root. stdout/stderr сервиса перенаправляются в
`/var/log/<name>.log`; состояние супервайзора — в `/var/log/ksersys.status`,
а его журнал — в `/var/log/ksersys.log`.

Интерактивный режим (`ksersys`) показывает список сервисов и live-PID;
Enter запускает/останавливает, E переключает `enabled`, A добавляет сервис,
R переключает политику перезапуска. Те же действия доступны из shell:
`ksersys status|start NAME|stop NAME|restart NAME|enable NAME|disable NAME|add NAME PATH [scope] [account]`.
Изменения правки записываются обратно в `/etc/services` и сохраняются между
загрузками. Обычный пользователь видит список и может управлять только своими
сервисами; правка файла и системные сервисы требуют root (`sugo ksersys`).

### POSIX-слой и сигналы

`src/user/posix.h` даёт компактный POSIX-фасад над ABI: `getpid`, `getuid`,
`getgid`, `waitpid`, `chdir`, `getcwd`, `mkdir`, `rmdir`, `unlink`, `stat`,
`usleep` и константы сигналов из `src/shared/signal.h`. Утилита `posixinfo`
показывает pid/uid/gid/cwd и `stat` по пути — это живой пример слоя.

Сигналы пока кооперативные: `kill <pid> [TERM|KILL|number]` сохраняет код выхода
(130 для TERM/INT, 137 для KILL) и флаг прерывания; процесс завершается на
следующем syscall или тике. `SIGKILL` не мгновенный: ядро не имеет асинхронной
доставки сигналов. Обычный пользователь может сигналить только процессам со
своим euid, root — всем, кроме init.

Изменения ФС доступны как файл: `/proc/events` содержит кольцевой журнал
строк `OP /path` (`CREATE`, `MKDIR`, `WRITE`, `UNLINK`, `RMDIR`, `RENAME`).
Это простой аналог inotify в духе «всё — файл»: подписка — это `open` + periodic
`read`, без отдельного syscall. Журнал ограничен 1 KiB.

При нехватке страниц (меньше 256 свободных) ядро раз в 100 тиков выбирает самый
«тяжёлый» не-init процесс и посылает ему кооперативный `SIGKILL`, записывая
`[OOM] killed pid ...` в журнал. Это примитивный OOM-killer, а не полная политика
с oom_score и cgroups.

### Звук и аудиофайлы

Ядро определяет OPL2/YM3812 и использует его как 9-голосный FM-синтезатор с
четырьмя тембрами (koto, flute, bell, bass) и настоящей регуляцией громкости;
если OPL2 нет, включается PC Speaker (clamp частоты 20–20000 Гц, иначе делитель
таймера переполнялся). `soundctl` показывает бэкенд и громкость, `volumectl`
меняет её, а значение сохраняется в `/etc/volume.cfg` и применяется init при
загрузке. Звуковые syscalls доступны и фоновым процессам, поэтому музыкальная
служба не требует foreground-сессии.

`klisten` проигрывает текстовые файлы `.KMS` из `/etc/music`:

```text
# freq duration_ms instrument ; 0 = пауза, instrument 0..3
294 220 0
330 220 1
```

Файлы `GARDEN.KMS` и `SAKURA.KMS` устанавливаются в образ вместе с ELF.
`kmusa` генерирует мотивы с разными тембрами, Enter — новый мотив, P — проигрыш.

**OST KRrawl.** В `/etc/music` установлены четыре японских по духу темы:
`SAKURA.KMS` (тихая «Сакура»), `TSUKI.KMS` («Луна»), `MATSURI.KMS` (праздничный
ритм) и `KAGE.KMS` (тёмная тема босса). KRrawl загружает их как общий `kms_track`
через `src/user/kms.c` — тот же парсер, что использует KListen. Во время игры
`M` переключает OST, `Shift+M` выключает/включает звук, название текущей темы
показано в правой панели. Темп берётся из длительностей нот, а тембр — из поля
`instrument`, поэтому OPL2 звучит полифонно, а PC Speaker получает те же ноты
в монофоническом режиме.

Игры и UI используют те же syscalls для эффектов.

### kintsugifetch

`kfetch` показывает компактную системную карточку в стиле neofetch: пользователь,
хост, версию ОС и ядра, оболочку, разрешение, ФС, аудиобэкенд, uptime, число
процессов, свободную память и громкость.

### KRrawl

`krrawl` запускает пошаговую игру: @ — герой, g — монстр, > — следующий этаж.
Стрелки/WASD перемещают, Space атакует четырёх соседей, Q выходит. Монстры
преследуют героя вблизи. Каждый этаж генерируется заново с гарантированной
дорогой до лестницы. Игра также доступна в меню KiWi и клавишей R в KTUI.
Текущая версия использует фиксированный seed и не сохраняет прогресс.

### Shell

После входа init очищает экран, и shell появляется на чистом терминале.
Prompt показывает пользователя и текущий каталог: `[user@kintsugi /home/user] $`,
у root — `#`. При редактировании строки знак **не меняется**: user всегда видит
`$`, root всегда `#` (старый совместимый префикс `!#>` убран). `whoami`, `id`,
`sugo`, `help` и работа с окружением встроены в shell.

## Темы и общая библиотека

`ksettings` теперь разделяет «Cell size» (совместимые 75/100/125%) и «Font size»
(75/100/125/150%). Размер шрифта меняет реальные пиксели ячейки через
`KOS_SYS_FRAMEBUFFER_FONT_SIZE`, сетка остаётся 80×25; профиль сохраняется в
`/ETC/VIDEO.CFG` пятым байтом. KTTE по-прежнему редактирует TUI-темы.

Новые темы GOLD и FOREST устанавливаются в `/ETC/THEMES`. KTTE сохраняет
совместимый формат `XX=YY`, поддерживает U undo/redo последней правки и Shift+C
для исправления одинаковых цветов текста и фона. Shift+A применяет тему.
16 цветов фона в framebuffer работают без VGA-мигания.

`ktuilib` предоставляет `tui_event_read`, hit testing, mouse-aware меню,
вкладки, прогресс, системную строку, экспорт тем и `tui_launch` с сохранением
кода ошибки spawn/wait. Общие поля, командная строка, pager, KUNED и базовые
движения/удаление VIK учитывают UTF-8. Сетка совместимости остаётся **80×25**:
больше пикселей увеличивает размер ячеек, а не рабочее число колонок.

Системная панель видна во всех старых приложениях: свободная RAM, uptime,
раскладка и состояние прокрутки. KInfo дополнительно показывает процессы и мышь.

## Процессы и безопасность

Каждый процесс несёт uid/gid/euid/egid, унаследованные от родителя; init
работает как root (PID 1) и запускает оболочку выбранного пользователя через
одноразовый pending-uid. `sugo` проверяет пароль root в ядре и только затем
запрашивает повышение для следующего дочернего процесса. KPROCM может завершить
себя, shell и другие обычные процессы; чужие процессы защищены проверкой
uid/euid, а root может завершать любые. Только init защищён от завершения; его
задача — перезапускать shell. Завершение самого менеджера возвращает
пользователя в shell с кодом 130. Подтверждение остаётся обязательным.

Новые syscalls 40–43 проверяют userspace-диапазоны; управление экраном, раскладкой
и доступ к мыши требуют foreground-сессии. Syscalls 56–66 отвечают за uid/gid,
вход, повышение прав, управление учётными записями и проверку пароля. Опасные
встроенные команды ядра (перезагрузка, системные операции) отклоняются для
не-root. Framebuffer остаётся supervisor-only, ring3 не получает прямого доступа
к MMIO. Лимит таблицы процессов пока 16.


## Pixel GUI (kgui)

Команда `gui` (или `kgui`) запускает отдельный графический режим в стиле Windows 95:
десктоп, панель задач, Start-меню с Program/Search/Run/Help/Shut Down, настоящие
перекрывающиеся окна с keyboard/mouse focus, drag/resize, minimize/maximize/close,
двойную буферизацию и обновление только dirty-прямоугольников. В комплекте KGFM,
KGED и KGTERM. Старый TUI-режим и syscall 7 сохраняются для совместимости.

Значки на рабочем столе (`My Computer`, `Terminal`, `Editor`, `Trash`) активны:
одинарный клик выделяет, двойной открывает соответствующее окно. Все пункты
меню Start и подменю Programs работают и мышью, и клавиатурой; приложения,
запущенные из меню, выводят текст в KGTERM. KGTERM — полноценный оконный шелл
с приглашением пользователя, историей (стрелки вверх/вниз) и командами
`help pwd cd ls cat echo mkdir rmdir rm touch date uptime free ps history clear exit`;
остальные команды запускаются из `/BIN` с выводом в окно. KGFM открывает файлы
двойным кликом в Notepad, одинарный клик только выделяет. KGED поддерживает
выбор инструмента и цвета мышью; мазок интерполируется между событиями мыши,
поэтому быстрые движения не рвут линию.

KGFM оформлен в стиле Windows 95: панель Back/Up/New/View, строка Address,
заголовки колонок Name/Size, строка состояния с числом объектов. Правый клик
по списку открывает контекстное меню (New File, New Folder, Open, Rename,
Delete, Properties), правый клик по рабочему столу — меню рабочего стола.
Меню File/Edit/View/Help в заголовке окна имеет рабочие пункты.

TUI-приложения (`kinfo`, `kiwi`, `kpaint`, `kset` и др.), запущенные из KGTERM,
выполняются в дочернем процессе: ядро перенаправляет их syscall 7 в буфер
захвата, а компоновщик рисует 80×25 клеток внутри окна. Клавиши передаются
дочернему процессу, Esc всегда закрывает сеанс; после выхода геометрия окна
восстанавливается. Приглашение терминала рисуется в общей области вывода,
а не в отдельном поле. Notepad поддерживает ввод, переводы строк и сохранение
через File → Save.


## GUI Administration

В Start-меню есть `kadms`: плавающее окно с root-паролем и командой. Пароль
проверяется через `KOS_SYS_AUTH`, а команда запускается через `KOS_SYS_ELEVATE`.
