# Базовая система: файловый API, процессы и выключение

## Файлы

Общий descriptor API: `open`, `close`, `read`, `write`, `dup2`, `pipe`,
`seek`, `fstat`, `ftruncate`, `sync`. Функции возвращают отрицательный код
ошибки; `kos_error(code)` даёт общее с ядром описание. Отдельного errno нет.
Read/write могут возвращать частичный результат; `write_all` повторяет запись.
Одна операция read/write ограничена 4096 байтами. EOF — ноль.

Флаги open:

- `KOS_O_READ`, `KOS_O_WRITE` — хотя бы один обязателен;
- `KOS_O_APPEND` — запись в конец и обновление общей позиции;
- `KOS_O_CREATE` — создать отсутствующий файл;
- `KOS_O_TRUNC` — очистить существующий файл, требует WRITE;
- `KOS_O_EXCL` — ошибка при существующем файле, требует CREATE.

`dup2` и наследование используют общую позицию открытого файла.
`ftruncate` требует доступ на запись и не меняет позицию. `fstat` пока
поддерживается только для обычных файлов. Seek за EOF допустим; при записи
промежуток заполняется нулями. Доступ на запись проверяется уже при open.

ФС остаётся FAT12/ASCII 8.3. Реализация write/truncate переписывает ограниченный
буфер файла целиком; это не потоковая ФС для больших файлов. Успешные unlink
и rename по-прежнему консервативно инвалидируют файловые дескрипторы через
общую generation. Неуспешные операции больше их не инвалидируют.
UNIX-семантика открытого удалённого inode пока не реализована.

## Процессы и память

`spawn` возвращает PID либо отрицательную ошибку; `wait` — статус завершения
непосредственного ребёнка, при отсутствии ребёнка — ECHILD.
`kill(pid)` запрашивает завершение со статусом 130. INIT, shell и вызывающий
процесс защищены. Это минимальный запрос прерывания, не POSIX signals;
завершение выполняется на безопасной точке syscall/возврате в userspace.
Система пока однопользовательская, разграничения по UID нет.

При выходе закрываются дескрипторы; wait освобождает адресное пространство,
kernel stack, окружение и terminal snapshot. Сироты помечаются для автоматической
уборки после завершения; процесс не освобождает собственный выполняемый стек.
Неудачное увеличение пользовательского heap откатывает добавленные страницы
и пустые page tables. Успешный malloc/free переиспользует память внутри
процесса; обычный free не возвращает страницы PMM до завершения процесса.

## Shutdown

`shutdown` заменяет `qemushutdown`. Порядок:

1. Отключить прерывания и прекратить выполнение других процессов.
2. Освободить их ресурсы и закрыть дескрипторы текущего процесса.
3. Выполнить ATA CACHE FLUSH для обнаруженных дисков.
4. Прочитать BIOS ACPI RSDP/RSDT/FADT/DSDT и запросить S5.
5. Если выключение не поддержано — вывести сообщение и остановить CPU.

Проверяются контрольные суммы и размеры таблиц. Поддерживается небольшой
ACPI legacy I/O subset с literal `_S5` package; нет общего AML interpreter,
XSDT-only firmware, hardware-reduced ACPI и UEFI. Фиксированных QEMU-портов
выключения больше нет. При ошибке flush предупреждение записывается в журнал;
выключение продолжается, сохранность данных не обещается.

`sync` явно синхронизирует ATA. Запись FAT уже выполняется синхронно;
буфера отложенных записей VFS нет. Reboot и halt отменяются при ошибке sync.
Shutdown не сохраняет несохранённые буферы редактора и не выполняет пользовательские
shutdown-hooks. Это аварийно-простой останов без SIGTERM grace period.

## Диагностические TUI

- `kbsm` — ресурсы, физические страницы, kernel heap, суммарный committed user
  heap, число процессов и открытых дескрипторов. Space действительно замораживает
  снимок, D переключает пояснения.
- `kmemman` — отдельная команда Memory Manager из того же исходника, без
  дублирования логики. Только чтение; освобождать чужие страницы нельзя.
- `kprocm` — детали открытых дескрипторов; K с подтверждением запрашивает
  завершение выбранного процесса.
- `kdiskman` — модель ATA, размер устройства в секторах, S синхронизирует диски,
  C проверяет FAT без исправления.
- `ktui` — пункт 8 запускает KMEMMAN.

Ядро и ELF нужно пересобирать вместе: диагностические структуры ABI расширены.

## Проверки

FDCHECK проверяет pipes/EOF/EPIPE, dup/seek, ошибки wait/kill, восемь циклов
spawn/kill/wait, сохранность дескриптора после неудачного unlink. При наличии
тестового FDTEST.TXT дополнительно проверяет truncate/stat/append/create/exclusive.
Smoke-тест создаёт fixture, открывает KMEMMAN и завершает машину командой
shutdown; проверяются COM1-записи sync/S5 и выход QEMU, затем fsck.fat.

Это усиление текущей базы, не заявление о завершённой POSIX-совместимости,
crash-consistency FAT или проверке всех возможных аппаратных ошибок.
