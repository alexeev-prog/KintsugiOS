# KintsugiOS GUI: большой реворк 2026

Версия документа: 1.0. Статус: реализовано в `src/user/kgui.c`, `src/user/gfx.c`,
`src/kernel/user/process.c`, `src/user/desktopabi.h`.

Этот документ — технический контракт графического стека после крупного
реворка. Он описывает **что было сломано**, **какие инварианты введены**,
**какие алгоритмы и структуры данных используются**, и **как проверять**
результат. Документ дополняет `GUI_NEXTSTEP_DESIGN.md` (визуальный язык) и
`GUI_ROADMAP.md` (план работ).

---

## 1. Цели реворка

1. **Детерминированность отрисовки.** Любой видимый пиксель должен быть либо
   перерисован в текущем кадре, либо его изменение должно быть запрещено.
   Не существует «забытых» прямоугольников.
2. **Единый источник истины для геометрии.** Пойнт, клик, подсветка и грязный
   прямоугольник вычисляются одной функцией. Запрещены дублирующие константы
   вида `44` в отрисовщике и в hit-test.
3. **Плавность без перегрузки шины.** Анимации работают через dirty-rect и
   injection в event pump, а не через perpetual full-frame repaint.
4. **Интерфейс, который невозможно случайно сломать.** Кнопки, иконки и меню
   имеют одинаковую семантику на всех темах; текст контрастен.
5. **Computer science вместо магии.** Каждая подсистема описана как конечный
   автомат, чистая функция или riot-структура с известной сложностью.

## 2. Аудит: найденные дефекты и их первопричины

| ID | Симптом | Первопричина | Исправление |
| --- | --- | --- | --- |
| B1 | «Обрывки» контекстного меню после закрытия | Меню рисовалось поверх окон, но при закрытии его прямоугольник не добавлялся в `gfx_dirty`: ветка partial-repaint трогала только активное окно | `overlay_bounds()` + `overlay_prev`; оба прямоугольника (старый и новый) объединяются в кадр |
| B2 | Клик по меню у края экрана не срабатывал | Отрисовка использовала clamped/flipped прямоугольник, hit-test — сырые `context_x/y` | `context_menu_rect()` — единственная функция геометрии для paint, hover и hit-test |
| B3 | След за курсором | Дополнительный слой тени `(x+1,y+1)` сохранялся не во всех путях; при partial recompose старые пиксели возвращались | Теневой слой удалён; остался только спрайт с полным capture/restore; `drag_move()` вызывает `cursor_erase()` до записи в `desktop` |
| B4 | Иконки на рабочем столе кликались «мимо» | Hit-test хардкодил `x+20`, `y+38`, а painter рисовал 18×18 + подпись переменной ширины | `desktop_icon_rect()` используется и в `compose()`, и в обработчике мыши |
| B5 | Подписи иконок пропадали на светлых обоях | Текст рисовался белым с прозрачным фоном | Подпись получила утопленную плашку в цвете темы и контрастный `gui_theme.text` |
| B6 | Док уезжал под системный трей | Число иконок считалось без учёта доступной ширины; painter и hit-test использовали разные ограничения | `dock_layout()` вычисляет ёмкость `floor((tray_x-22)/44)`; оба цикла используют `running_count` |
| B7 | Текст становился нечитаемым в тёмных темах | `GFX_BLACK` хардкодился на поверхности `GFX_FACE` | Введён `GUI_INK == gui_theme.text`; все такие поверхности используют его |
| B8 | Дубли окон при повторном запуске | Каждый launch создавал новое окно | `activate_window_kind()` поднимает существующее; для внешних клиентов — `text_equal_ci()` + `gfx_window_raise()` |
| B9 | Разрушение окна во время обхода `zorder` | `window_finish()` вызывался из цикла `compose()` и менял массив на ходу | Отложенный teardown: `pending_close[]`, обработка после `gfx_present_dirty()` |
| B10 | Анимации дёргались | Линейный scale и отсутствие dirty-обработки для областей вне окна | Ease-in/ease-out таблицы; dock добавляет полосу над доком в dirty |
| B11 | Выбор обоев был неудобен | 6 текстовых кнопок, два «циклических» цвета без предпросмотра | 8 превью-тайлов, две палитры по 10 swatch, числовой масштаб |
| B12 | Уведомление обрезалось | Ширина toast хардкодилась в 320 px | Ширина = `text_width + 24`, ограничена экраном |
| B13 | Настройки разрешения применялись мгновенно | Смена видеорежима на ходу меняет geometry retained-поверхностей | `/etc/VIDEO.CFG`, применяется `init` на старте; UI честно сообщает об этом |
| B14 | Повторное открытие Settings создавало копию | Отсутствовала проверка | `activate_window_kind(5, "Settings")` |

## 3. Инварианты (проверяются визуально и код-ревью)

1. **I1 — Geom unity.** Для любого интерактивного объекта существует ровно
   одна функция, возвращающая `(x, y, w, h)`. Painter, hit-test и dirty
   пользуются ею. Нарушение I1 = B1/B2/B4/B6.
2. **I2 — Overlay lifetime.** Если оверлей открыт, его bbox входит в `dirty`.
   Если оверлей был открыт в прошлом кадре, его bbox тоже входит в `dirty`
   (при закрытии новый bbox пуст). Это следствие I1 для временных объектов.
3. **I3 — Cursor atomicity.** Любая запись в `desktop` вне `compose()` обязана
   быть окружена `cursor_erase()` … `cursor_move()`. Гарантирует отсутствие
   «призраков» указателя.
4. **I4 — Deferred mutation.** Нельзя изменять `zorder[]`/`windows[].used`
   внутри цикла, который этот массив обходит. Все удаления — через
   `pending_close[]`.
5. **I5 — Theme ink.** Любой текст на `GFX_FACE` рисуется `gui_theme.text`.
   Белый/чёрный допустим только на фиксированном контрастном фоне (например,
   белое поле ввода).
6. **I6 — Bounded layout.** Любая горизонтальная компоновка ограничена
   `screen_width - TRAY_WIDTH`; переполнение усекается по счётчику, а не
   «рисуется поверх».
7. **I7 — No floats.** Прошивка собирается `-msoft-float` без libgcc-float,
   поэтому все дробные коэффициенты — fixed-point `num/den` или таблицы.
8. **I8 — Persistence.** Пользовательские изменения выживают перезапуск
   (`KGUI.CFG`, `VIDEO.CFG`) и не требуют пересборки.

## 4. Структуры данных

```c
typedef struct {
    int used, x, y, width, height;
    int saved_x, saved_y, saved_width, saved_height;
    int minimized, maximized;
    int anim_open, anim_progress, anim_close;  /* state machine окна */
    ...
} gui_window;                    /* MAX_WINDOWS = 12, static pool */

int zorder[MAX_WINDOWS];         /* перестановка индексов; swap-to-top O(n) */
gfx_dirty overlay_prev;          /* bbox последнего оверлея */
int pending_close[MAX_WINDOWS];  /* отложенный teardown */
int dock_mag_key, dock_mag;      /* один анимируемый тайл 0..100 */
int dock_hover_key;              /* целевой тайл */
u32 cursor_save[CURSOR_WIDTH*CURSOR_HEIGHT]; /* retained background pointer */
```

Выбор static pool вместо dynamic allocation объясняется средой: 12 окон ×
~9 КБ = фиксированный бюджет, фрагментация heap исключена, а hit-test —
линейный обход длиной 12 (cache-friendly, дешевле любой хеш-таблицы на таких
размерах).

## 5. Алгоритмы и сложность

### 5.1 Композитор (retained mode + damage tracking)

```
frame:
  input → state change → changed flag
  overlay_bounds() → union(prev, now, dock strip)
  compute frame dirty:
    external_only | live_window | focused-window | full
  union with overlay bbox
  for each window ∩ dirty: draw_window(surface)
  compose: wallpaper ∩ dirty → icons ∩ dirty → windows ∩ dirty
           → external clients → menus → taskbar → present(dirty)
  process pending_close
  cursor repaint
```

Сложность: `O(W + I + E + O)`, где `W ≤ 12` окон, `I = 4` иконки,
`E ≤ 8` внешних клиентов, `O` — число активных оверлеев (≤3).Present
передаёт только объединённый прямоугольник: `gfx_present_dirty()`.

### 5.2 Overlay invalidation (доказательство корректности)

Пусть `R_t` — bbox оверлея в кадре `t`, `R_{t-1}` — в предыдущем. В кадре `t`
мы добавляем в dirty `R_{t-1} ∪ R_t`. Если оверлей закрылся, `R_t = ∅`,
значит `R_{t-1}` перерисовывается из wallpaper/окон → старые пиксели
уничтожены. Если оверлей открылся, перерисовывается `R_t`. Если переместился —
оба. Если оверлей не менялся, `R_t ⊆ dirty` по I2. След: ни один пиксель
оверлея не может «зависнуть» между кадрами.

### 5.3 Док: арифметика компоновки

```
tray_x   = screen_width - TRAY_WIDTH
capacity = floor((tray_x - 16 - 6) / DOCK_SLOT)   /* DOCK_SLOT = 44 */
running  = min(used_windows, capacity - 6)
icons    = 6 + running                            /* launcher + 5 pinned */
width    = icons*DOCK_TILE + (icons-1)*6 + 10      /* DOCK_TILE = 38 */
start_x  = max(8, (tray_x - width)/2)
```

Expansion limit: `used_windows > capacity-6` приводит к усечению списка —
не к переполнению трея. Один и тот же `drawn` счётчик используется painter и
hit-test.

### 5.4 Magnification (easing)

Конечный автомат с одним владельцем анимации:

```
target = dock_hovered_index()           /* -1 | 0..5 | 100+index */
if owner != target && mag > 0: mag -= ceil(mag/8)   /* retract */
   when mag == 0: owner = target
else if owner == target && target >= 0: mag += ceil((100-mag)/8)
else: owner = -1
```

Инвариант: в любой момент максимум один тайл увеличен. Это исключает
«две иконки выросли» и мерцание. `dock_tick()` возвращает `animating`, что
поддерживает event pump живым ровно столько кадров, сколько нужно.

### 5.5 Анимации окон

Небольшие fixed-point таблицы (11 кадров). Open — ease-out (быстрый старт,
мягкая посадка), close — ease-in (ускорение к исчезновению). Масштаб задаётся
`num/40 ∈ [0.75, 1.0]`; `gfx_blit_scale()` использует целочисленную выборку
`src = dst * den / num`, без float.

### 5.6 Обойный генератор

`wallpaper_pattern(kind, x, y, scale)` — **чистая функция**. Она используется как для
полноэкранного surface и для 8 мини-превью в Settings. Сложность генерации
полного кадра `O(W·H)` с четырьмя целочисленными операциями на пиксель;
вызывается только при смене параметров, не в кадровом цикле. Паттерны:
Solid, Grid, Diagonal, Checker, Dots, Stripes, Weave, Ripple.

### 5.7 Пиктограммы

`draw_pictogram(s, x, y, size, kind, color)` — параметрический векторный
примитив. Цвет штриха выбирается по percептивной яркости фона
(`77R+150G+29B`, веса Rec.601, integer). Виды: launcher, folder, editor,
terminal, monitor, system, trash. Один и тот же набор используется на рабочем
столе, в доке и в KGFM, что устраняет разностильность и упрощает обновление иконок.

## 6. Ввод и состояния

### 6.1 Event pump

```
mouse sequence changed? → gui_mouse = raw (без margin)
                         mouse.x/y += GUI_CURSOR_HIT_MARGIN  (только hit-test)
only motion? → cursor_move + hover update
button press → context → dialog → menubar → dock → windows → desktop
key → modal dialog → global menu → start menu → focused window → WM keys
```

`GUI_CURSOR_HIT_MARGIN = 2` расширяет цель для тонких элементов, не меняя
видимый курсор.

### 6.2 Контекстное меню

Состояние: `context_open`, `context_x/y` (raw), `context_hover`,
`context_count`, `context_items[10][32]`. Geometry — `context_menu_rect()`.
Переходы: открыть (right click), выбрать (`context_action`), закрыть (click
outside / Esc), переоткрыть (другой right click). Каждый переход выставляет
`changed = 1`; I2 гарантирует очистку.

### 6.3 Окна

`anim_open → normal → anim_close → pending_close → freed`. `close_window()`
не освобождает ресурсы сразу, а переводит окно в `anim_close` и переносит его
на верх `zorder` (видимость на время анимации). `window_finish()` вызывается
только после `gfx_present_dirty()`.

## 7. UI/UX решения

* **Dock** — единая центрированная полоса; Running indicator; "compacted"
  состояния для свёрнутых окон; magnify с easing. Системный трей — отдельный
  закреплённый регион справа.
* **Wallpaper chooser** — 8 живых превью (рисуются тем же алгоритмом, что и
  реальные обои), две палитры A/B с явным активным swatch, числовой масштаб.
  Пользователь видит результат до применения.
* **Settings** — окно 640×500, четыре вкладки; новая компоновка не выходит
  за границы на 1024×768.
* **Launch** — GUI/TUI/CLI и внешние клиенты идут через единый dispatcher:
  если приложение уже запущено — оно поднимается; если нет — создаётся ровно
  один экземпляр; ошибка показывается toast.
* **Time** — CMOS RTC (`KOS_SYS_RTC`), fallback на uptime.
* **Контраст** — `GUI_INK` и `icon_ink()` учитывают тему и яркость подложки.

## 8. Производительность и бюджет

| Операция | Частота | Стоимость |
| --- | --- | --- |
| `cursor_move` | каждое движение мыши | 12×16 pixel capture/paint + present dirty 13×17 |
| `dock_tick` | каждый кадр | O(1), без syscall |
| `overlay_bounds` | каждый changed-кадр | O(1) union до 4 rects |
| `draw_taskbar` | каждый changed-кадр | O(dock_icons + 1 RTC syscall) |
| `wallpaper_generate` | только по изменению | O(W·H) |
| `compose` | changed-кадр | O(W+I+E+O), present только dirty |

`SLEEP(10)` в event loop даёт 100 Гц опрос без busy wait. Если изменений нет,
кадр не presents вообще.

## 9. Совместимость и обратная совместимость

* `gfx_*` API сохраняет сигнатуры для внешних приложений; добавлены только
  `gfx_blit_scale` и `gfx_text_scaled` (fixed-point).
* `KOS_SYS_RTC = 93` добавлен в `desktopabi.h`; старые syscall-номера не
  изменились.
* `VIDEO.CFG` остаётся 5-байтовым форматом; GUI пишет допустимые значения
  (mode < `KOS_VIDEO_MODES`, scale < `KOS_FRAMEBUFFER_SCALES`).
* `KGUI.CFG` — текстовый `key=value`; новые ключи не требуют миграции.

## 11. Известные ограничения

* Смена видеорежима в рантайме не поддерживается намеренно: КГИ держит
  retained-поверхности фиксированного размера. Изменение применяется при
  следующем старте через `init`.
* `KOS_SYS_DISPLAY` требует foreground; GUI поэтому не дёргает его напрямую.
* Внешние GUI-клиенты рисуются после собственных окон компоновщиком; для
  них нет анимации открытия (ядро владеет их surface).
* QEMU smoke test в окружении разработки останавливается до запуска
  userspace (`[INIT] userspace init ready`) — это воспроизводится и на чистом
  userland и не зависит от GUI-правок. Визуальная верификация требует
  рабочего userspace-окружения.

## 13. Итог

Реворк превратил компоновщик из набора «эвристик закрашивания» в систему с
явными инвариантами: геометрия — одна функция на объект, временные объекты —
всегда в dirty, удаление — после обхода, анимации — конечные автоматы с
fixed-point временем. Это устраняет корневые причины «артефактов», а не их
симптомы, и даёт предсказуемую, измеримую плавность при бюджете 100 Гц event
pump.
