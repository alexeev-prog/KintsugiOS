# Скрипты, окружение, pager и журнал

## Скрипты

`sh /HOME/DEMO.SH arg` запускает отдельный процесс shell. Также можно выполнить
`/HOME/DEMO.SH arg` напрямую. `source /HOME/DEMO.SH` или `. /HOME/DEMO.SH`
исполняет файл в текущей оболочке: изменения окружения и каталога сохраняются.
`exit [0–255]` завершает текущую оболочку; в sourced-файле это тоже выход из shell.

```sh
#!/BIN/SHELL.ELF
# Одна команда на строку
echo "Hello $1, arguments: $#"
echo "Home: ${HOME}; last status: $?"
echo 'Literal $HOME'
echo log-data | cat > /HOME/RESULT.TXT
```

Поддерживаются LF/CRLF, последняя строка без newline, комментарии `#`, аргументы
`$0`–`$9`, `$#`, `$?`, `$NAME`, `${NAME}`, кавычки, pipes и перенаправление вывода.
Строка скрипта ограничена 255 байтами, раскрытая команда — 4095 байтами;
вложенность source — 8. Скрипт продолжает работу после неуспешной команды,
возвращает статус последней команды. Бинарные NUL и слишком длинные строки
отвергаются. Это не POSIX shell: пока нет циклов, if, функций, heredoc и подстановки
команд. Прямой запуск `.SH` реализован для одиночной foreground-команды;
для pipeline/фонового запуска используйте `/BIN/SHELL.ELF /HOME/DEMO.SH`.
Раскрытое значение остаётся одним аргументом (нет word splitting/globbing)
и не превращается в оператор shell. Shebang распознаётся как комментарий shell,
а не отдельным механизмом ядра.

## Окружение

```sh
export DEMO="some value"
echo "$DEMO"
env
unset DEMO
export PATH=/BIN:/HOME
```

До 24 переменных на процесс: имя до 31 байта, значение до 191 байта.
Окружение копируется при spawn и запуске pipeline; ребёнок не меняет родителя.
`PATH` задаёт поиск ELF-команд через `:`, `HOME` используется командой `cd` без
аргументов. Значения по умолчанию: PATH=/BIN, HOME=/HOME, TERM=kintsugi.
Изменения не сохраняются автоматически между перезагрузками. Приложения имеют
runtime API getenv/setenv/unsetenv и syscalls 35/36; ядро и ELF обновляются вместе.

## Pager

```sh
pager /HOME/RESULT.TXT
journal | pager
cat /README.TXT | pager
```

Стрелки — строка, PageUp/PageDown и Space — страница, Home/End — начало/конец,
q/Esc — выход, Ctrl+T — тема. Ввод сначала читается до EOF: это bounded viewer,
не live-tail. Лимит 512 КиБ и 32768 отображаемых строк; длинные строки переносятся
по 78 колонок. Символы вне печатного ASCII отображаются пробелами.

## Журнал

`journal` выводит RAM-журнал; `journal --save /BOOT.LOG` экспортирует снимок.
Можно использовать `journal | grep ERROR`. Старый `klog` также остаётся доступен.
Буфер увеличен до 32 КиБ: при заполнении старые байты вытесняются. Сохранение
явное, без автоматической записи на диск и без рекурсии логирования через ФС.

Новые записи имеют последовательный номер, время в тиках PIT (50 Гц), уровень
DEBUG/INFO/WARN/ERROR и компонент. Старые диагностические записи сохраняют свой
формат. COM1 получает те же сообщения; panic работает без heap и ФС.

Загрузка фиксирует BIOS handoff, версию, IDT/PIC, E820/PMM, heap, ring3/TSS,
терминал, установку PIT/PS2, ATA probing/model/capabilities, FAT12 BPB/геометрию,
результат проверки тома, mount и запуск INIT. ELF loader пишет путь, PID, entry
и размер payload. Ошибка записи FAT фиксируется и отключает дальнейшие мутации.
Это диагностический журнал реализованных подсистем, не дамп каждого порта и
сектора; драйверов PCI/USB/AHCI в текущей базе нет.

Хостовый лог всей сессии: `make run QEMU_FLAGS="-serial file:serial.log"`.
